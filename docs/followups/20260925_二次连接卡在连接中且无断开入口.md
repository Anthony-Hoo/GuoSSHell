# 二次连接可能卡在「连接中…」，且会话页没有断开入口

- 状态：待办
- 记录日期：2026-09-25

## 现状

- 连接请求要等会话视图报出几何才发出（`terminal_page.dart` 的 `_pendingConnect` /
  `_onTerminalResize`）。几何经 `FrameTerminal.resize` 上报，它对「与上次相同的几何」去重，
  而 `FrameTerminal` 实例随页面常驻、去重状态从不复位。同一进程内第二次连接（例如密码
  输错后返回重连）若几何不变，`onResize` 不触发，连接请求永远不发，页面停在「连接中…」
  （代码推演，未实机复现）
- 页面的去抖状态（`_sent*` / `_pending*` / `_resizeTimer`）同样跨会话保留，新会话的
  第一次尺寸变化可能被当成重复吞掉
- 会话页只在「失败 / 已断开」横幅上有「返回」；连接中、已连接状态没有断开或取消入口，
  上面的情况只能杀进程

## 下一步

新会话开始时复位 `FrameTerminal` 与页面的会话级状态（去重、去抖、模式位、帧内容），
或连接时直接带上当前几何、连上后几何不同再补发一次 Resize；hub 侧 Connect / Resize
的行列钳到 ≥1。会话页补一个不压在终端区域上的断开入口（连接中为「取消」），
hub 在连接阶段同时监听 Disconnect，做到立即取消。
