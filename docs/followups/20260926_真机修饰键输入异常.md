# 真机修饰键输入异常

## 问题

实体键盘操作中，用户确认 Ctrl 和其他修饰键组合没有生效。远端未收到 `Ctrl+[` 对应的 Esc；
带 Option、Control、Shift 的点击没有对应修饰位或已验证的本地选区效果。
真机 XCUITest 的三种修饰键点击同样退化为普通左键点击。

## 现状

实体触控板的移动和双向滚轮有远端记录，说明 XCUITest 滚轮无上报不能推广到实体滚轮。
系统合成的单击、右键、双击和按住拖动已通过；模拟器上的原有系统输入用例通过。
修饰键异常已在实体操作中复现，不能仅归因于 XCTest 合成限制，也不能记为真机键鼠验收通过。

实体回车、退格和中文 UTF-8 提交有记录，但指定的英文大小写序列与中文词组未匹配。
字符按键的系统合成验收也未完成：中文拼音预编辑影响原始字节断言，XCTest 等待输入法动画可能长时间停顿。
Flutter 层注入的按键编码通过，不代表完整实体输入链路通过；现有证据不足以判定中文丢字。

终端按键与指针处理都读取 Flutter 的 `HardwareKeyboard` 修饰键状态。
当前没有同一次操作的 UIKit 与 Flutter 原始事件记录，尚不能区分系统设置、事件交付与 App 处理的问题。

## 下一步

在同一轮实体操作中记录 UIKit 按键事件、Flutter `KeyEvent` 与 `HardwareKeyboard` 状态、指针事件和远端字节，
确定修饰信息缺失的位置；同时核对硬件键盘修饰键映射和系统快捷键设置。
修复后分别以英文输入法核对大小写、Ctrl / Option 组合与修饰键点击，以中文输入法逐步核对选词、提交和取消。
保留 XCTest 滚轮覆盖限制，并继续使用实体滚轮记录作为该路径的验收证据。
